# What the study costs, and what $950 buys

Funding on hand: **$950**. Spent as of 2026-09-19: **$88.10**.
`STUDY_BUDGET_USD=950` is set in `.env`, so `spend.check_budget()` raises
before the next paid call once the ledger reaches it. Nothing is lost at the
stop: every finished run is on disk and `--resume` picks up where it left off.

## Measured cost per case (not estimated)

| arm | retrieval | letter | searches |
|---|---|---|---|
| ChatGPT (gpt-5.6-luna) | $0.11 | $0.02 | 15.1 |
| Gemini (gemini-3.5-flash) | $0.35 | ~$0.05 | 32.0 |
| Claude free (claude-sonnet-5) | $2.12 uncached / ~$0.80 cached | ~$0.30 | 22.7 |
| OrthoAppeals (Sonnet) | $0 — runs locally | $0.05 | 0 |

Grading is Opus at **$0.13/call**. Brave Search is **$5.00 per 1,000 requests**
at 50 req/s ([pricing](https://api-dashboard.search.brave.com/documentation/pricing)).

All four arms through all three stages: **$2.67 per case.**

## Finishing the pilot: ~$115

108 retrievals ~$62, 120 letters ~$21, 120 grades ~$19, ~3,000 searches ~$15.
Pilot lands at about **$205** all-in.

## The main study will not be 400 cases at this budget

400 cases x 4 arms is **~$1,070** — and $812 of that is retrieval, letters and
search alone, before a single letter is graded. After the pilot there is ~$745
left, so 400 does not fit even with grading switched off.

**300 cases fits with room to spare: ~$673.**

| | 300 cases |
|---|---|
| retrieval (4 arms) | $378 |
| letters (4 arms) | $126 |
| Brave search | $105 |
| grading, subsample (below) | $64 |
| **total** | **$673** |

Running total: $88 spent + $115 pilot + $673 = **$876 of $950**, leaving $74.

### Why 300 is not a compromise on the primary endpoint

The pilot's primary result was 30/30 vs 15/30 — a 50-point gap at P<.001 on 60
cases. 400 was never about power for that comparison; it was about precision
inside the strata and across payers. 300 gives almost the same precision there
and costs $270 less.

### Grading a subsample, not every letter

The primary endpoint (did it name the governing policy) and the letter's
mechanical fields (appeal deadline, submission route, policy named, every
quotation verified against the policy text by string match) are **string
comparisons — they cost nothing** and run on all 1,200 letters.

Only the judged fields — uses_records, unsupported_attribution,
wrong_policy_cited, unfinished, completeness — need the Opus grader. Those run
on a random subsample of **400 letters (100 per arm)**, drawn with the study
seed and blinded the same way. That is ample for the error-rate comparison the
abstract reports (the pilot found 6.8% vs 21.7% on 60 per arm) and it takes
grading from $256 to $64.

### The number to watch

Grading has used 478 Opus calls for 120 letters — **4 calls per letter**. Nearly
all of that was the period when the grader returned incomplete JSON and every
incomplete grade was retried. That is fixed, and the forward rate should be near
1.1. If it is not, and 400 graded letters run at the old rate, grading costs
$250 instead of $64. Measure it deliberately: `grade_letters.py --limit 20`,
then divide the calls recorded by 20 before committing the rest.

### If money gets tight anyway, in order

1. Grade fewer letters. The mechanical outcomes are unaffected and free.
2. Drop to 250 cases (~$560).
3. Do **not** drop the Claude-free arm to save money. It is the only comparison
   where the model is held constant, so it is the one that isolates
   architecture from model — the whole claim of the paper.
4. Do **not** grade with Sonnet. It saves ~$200 and weakens the softest part of
   the design.
